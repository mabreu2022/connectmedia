# Connect Media — Banco de Dados Firebird 5.0

O sistema utiliza o **Firebird 5.0** como SGDB relacional embarcado/local.

---

## 🗄️ Esquema Relacional (DDL)

### 1. Tabela `TB_ASSUNTOS`
```sql
CREATE TABLE TB_ASSUNTOS (
    ID_ASSUNTO INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    NOME VARCHAR(100) NOT NULL UNIQUE
);
```

### 2. Tabela `TB_CANAIS`
```sql
CREATE TABLE TB_CANAIS (
    ID_CANAL INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    NOME_CANAL VARCHAR(150) NOT NULL,
    URL_YOUTUBE VARCHAR(255) NOT NULL UNIQUE,
    ATIVO SMALLINT DEFAULT 1
);
```

### 3. Tabela `TB_CANAL_ASSUNTO`
```sql
CREATE TABLE TB_CANAL_ASSUNTO (
    ID_CANAL INTEGER NOT NULL,
    ID_ASSUNTO INTEGER NOT NULL,
    PALAVRA_CHAVE VARCHAR(100) NOT NULL,
    CONSTRAINT PK_CANAL_ASSUNTO PRIMARY KEY (ID_CANAL, ID_ASSUNTO),
    CONSTRAINT FK_VINCULO_CANAL FOREIGN KEY (ID_CANAL) REFERENCES TB_CANAIS (ID_CANAL) ON DELETE CASCADE,
    CONSTRAINT FK_VINCULO_ASSUNTO FOREIGN KEY (ID_ASSUNTO) REFERENCES TB_ASSUNTOS (ID_ASSUNTO) ON DELETE CASCADE
);
```

### 4. Tabela `TB_VIDEOS_BIBLIOTECA`
```sql
CREATE TABLE TB_VIDEOS_BIBLIOTECA (
    ID_VIDEO INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ID_CANAL INTEGER NOT NULL,
    ID_ASSUNTO INTEGER,
    TITULO_VIDEO VARCHAR(255) NOT NULL,
    URL_VIDEO VARCHAR(255) NOT NULL UNIQUE,
    THUMBNAIL_URL VARCHAR(500),
    STATUS_DOWNLOAD VARCHAR(20) DEFAULT 'PENDENTE',
    FORMATO_DOWNLOAD VARCHAR(10) DEFAULT 'MP4',
    CAMINHO_ARQUIVO VARCHAR(500),
    PROGRESSO INTEGER DEFAULT 0,
    DATA_PUBLICACAO TIMESTAMP,
    DATA_CADASTRO TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT FK_VIDEO_CANAL FOREIGN KEY (ID_CANAL) REFERENCES TB_CANAIS (ID_CANAL)
);
```

### 5. Tabela `TB_CONFIGURACOES`
```sql
CREATE TABLE TB_CONFIGURACOES (
    ID_CONFIG INTEGER NOT NULL PRIMARY KEY,
    CAMINHO_DOWNLOADS VARCHAR(500),
    QTD_VIDEOS_BUSCA INTEGER DEFAULT 5,
    INTERVALO_MINUTOS INTEGER DEFAULT 60,
    DATA_INICIAL DATE,
    DATA_FINAL DATE,
    BUSCAR_VIDEOS SMALLINT DEFAULT 1,
    BUSCAR_SHORTS SMALLINT DEFAULT 1,
    BUSCAR_LIVES SMALLINT DEFAULT 1
);
```

## 🔒 Mecanismo de Concorrência e Lock (`.fdb.lock`)

O Firebird em sistemas Windows restringe acessos simultâneos concorrentes via ponte ISQL. Para solucionar o erro de colisão de processos e timeouts (`[ISQL Bridge] Timeout ao aguardar lock do banco de dados`):

- **Trava de Arquivo do Sistema (`Database/.fdb.lock`)**: Todos os processos (`Server.js`, `worker_download.js`, `popular_e_rodar.js` ou scripts avulsos) solicitam a trava exclusiva antes de executar chamadas via `executeISQLInternal`.
- **Auto-Recuperação de Lock Órfão / Mesma Instância**: Se o arquivo de lock pertencer ao mesmo PID do processo atual (`lockedPid === pid`) ou se tiver sido modificado há mais de 45 segundos (`lockAgeMs > 45000`), a trava é reconhecida como órfã e removida automaticamente antes da tentativa de aquisição.
- **Ajuste Dinâmico de Timeout e Backoff**: Aguarda com backoff exponencial (50ms a 500ms) até o tempo máximo de 30 segundos (30.000ms), correspondendo ao tempo limite de execução do binário `isql.exe`.
- **Sufixos Únicos em Scripts Temporários**: Cada query gera um arquivo `.sql` temporário contendo um sufixo alfanumérico aleatório (`isql_<pid>_<timestamp>_<random>.sql`), impedindo colisões de I/O em execuções paralelas.
- **Semáforo Concorrente no Worker (`isWorking`)**: Em `worker_download.js`, a execução do `setInterval` utiliza o controle `isWorking` para evitar requisições sobrepostas durante downloads ativos, prevenindo saturação na ponte ISQL.
